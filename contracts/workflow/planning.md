# Planning

**Keep three records separate** (domain contracts name defaults):
- **Intent**: purpose, constraints, non-goals; ideas marked expected, exploratory, or rejected. Inclusion is not authorization.
- **Design**: current structure, approved near-term decisions, labeled hypotheses. Don't build for deferred ideas.
- **Authorized work**: the work authority. Current outcome, acceptance criteria, exclusions, stop condition.

A design request authorizes design, not production. A complete design does not authorize a complete backlog.

When authorized work changes intent (capabilities, behavior, constraints, non-goals), update the intent record in the same increment. Mark approved-but-undelivered items as such; link the work authority instead of copying tasks.

**Limits**
- One active increment by default; up to three uncommitted next candidates. Neither is a target.
- Plan in detail only the active increment. No whole-project schedules or estimates unless asked.
- "Continue" means continue current scope. If done and scope is unclear, report and ask.
- A discovered dependency does not authorize new work. Explain and ask when it changes the outcome.
- Large outcomes split into reviewable increments; explicit authorization MAY allow a bounded sequence or parallel work (MA-COORD).
